# Backend Setup Guide

## Prerequisites

Everything needed is already in this project's Python environment --
`fastapi`, `uvicorn`, `sqlalchemy`, `pydantic`, `alembic`, `pypdf`,
`beautifulsoup4` (see `requirements.txt`). Nothing new needs to be
installed.

## Running locally

```
uvicorn backend.app.main:app --reload
```

- API docs (auto-generated by FastAPI): http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/health

On first run, a local SQLite database file is created automatically at
`backend/policylens_dev.db` (git-ignored — see `.gitignore`). No separate
database server needs to be installed or running.

## Configuration

Copy `.env.example` to `.env` and adjust if needed — every variable has a
working default (see `backend/app/config.py`):

| Variable | Default | Purpose |
|---|---|---|
| `APP_ENV` | `development` | |
| `DATABASE_URL` | `sqlite:///backend/policylens_dev.db` | Swap to a PostgreSQL URL later with zero model code changes. |
| `MAX_UPLOAD_SIZE_BYTES` | 20 MB | Policy-document upload size limit. |
| `LOG_COMMENT_TEXT` | `false` | Comment text is never logged unless explicitly opted into for local debugging. |

## Switching to PostgreSQL later

Set `DATABASE_URL` to a `postgresql://...` connection string. SQLAlchemy
handles the dialect difference; no model code changes are needed (the one
exception: the `check_same_thread` connect arg in
`backend/app/database.py` is SQLite-specific and is already conditional on
the URL prefix).

## This is separate from the annotation subsystem

`scripts/annotation/` (the single-annotator CSV-based research tooling
under `data/annotations/new_experiment/`) is a completely separate system.
The backend never reads from or writes to `data/annotations/`. The one
piece of code shared between them is `ml/stance_classification/
dataset_prep.py`'s `normalize_text()`, reused by
`backend/app/services/validation.py` so text normalization has one
implementation, not two subtly different copies.
